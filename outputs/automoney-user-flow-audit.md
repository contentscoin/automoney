# automoney 사용자 기능·콘텐츠·AI 연결 감사

기준일: 2026-09-22. 로컬 소스 기반 재검토. 운영 DB 내용, 로그인한 사용자의 화면, Vercel 환경변수, 실제 SNS 게시는 이번에 검증하지 않았다. 아래 확정 사항은 코드 동작이며 운영 증상 원인은 조건부로 구분한다. 전체 파일의 줄 단위 보안 감사나 모든 기능의 E2E 완료를 의미하지 않는다.

## 결론

기능별 백엔드와 화면은 있으나 신규 사용자의 콘텐츠 발견 → AI 준비 → 생성 → SNS 연결 → 첫 게시를 안내하는 통합 흐름이 없다. 이전 DEV-01~15 모두 DONE 보고는 이 흐름의 완성도를 보증하지 않으며, 아래 코드상 결함과 미검증 조건을 반영해 수정되어야 한다.

## 콘텐츠가 안 보이는 이유

1. 메뉴 자체: `apps/web/components/AppShell.tsx`의 aside가 `hidden ... md:block`. 작은 화면에서는 전체 메뉴가 사라지고 헤더에는 대체 메뉴가 없다. 데스크톱에서는 `/dashboard/content` 메뉴가 모든 역할에 포함된다.
2. 내 콘텐츠: `content.ingestGeneratedJob`은 기본 `PRIVATE`로 저장한다. 사용자 A가 만든 콘텐츠는 B에게 자동 노출되지 않는다.
3. 운영 제공 콘텐츠: `content.listLibraryFor`는 다른 사람의 콘텐츠 중 `SHARED + APPROVED`만 반환한다. SUPER_ADMIN의 매거진·콘텐츠 화면에서 승인 후 공유 전환이 필요하다.
4. 매거진: 운영자가 등록해야 한다. 매거진 등록은 소재 추출이지 모든 사용자에게 완성 게시물을 자동 생성하는 동작이 아니다.
5. 상품: 생성 선택기는 활성 상품을 반환한다. 실제 등록/활성 상태를 확인해야 한다.
6. 환경: 2026-09-26에 `wry-ermine-412`의 환경변수와 987개 문서를 백업·검증 후 `resilient-cheetah-311`으로 이관했다. `.env.production`, Vercel Production의 두 공개 Convex URL, 데스크톱 기본 site URL을 모두 production으로 통일했고 `LIVE_PUBLISH_ENABLED=false`를 유지한다.

## 콘텐츠 종류별 공급 방식

| 항목 | 실제 공급 방식 |
|---|---|
| 오늘의 매거진 | 운영자가 URL/HTML 등록 → 텍스트·이미지·상품 소재 추출 |
| 콘텐츠 라이브러리 | 개인 생성 결과 + 운영 승인·공유 콘텐츠 |
| 코디 제안 | 매거진 기반 코디 자료 |
| 짤·밈 | 운영 수동 등록 경로. 자동 밈 제작 기능으로 볼 수 없음 |
| 트렌드 | Google Trends KR RSS, 6시간 cron |
| 제품 정보 | 사용자가 상품 선택 후 제품 정보 팩 생성 |
| 연예인 착용 | 검색 provider 필요, 출처 후보를 저장. 이미지 재게시 허가를 뜻하지 않음 |

## GPT 연결과 게시 방법

현재 구현은 사용자의 PC에 있는 Codex CLI로 텍스트를 생성한다. 웹에서 OpenAI API 키를 등록하거나 ChatGPT 계정을 직접 연결하는 화면은 없다. 데스크톱 앱 설치가 Codex CLI 설치를 포함하지도 않는다.

코드가 기대하는 순서:

1. automoney 데스크톱 앱 설치·실행.
2. 웹 `/dashboard/devices`에서 페어링 코드를 발급하여 앱과 연결.
3. PC에 Codex CLI를 준비하고 해당 PC에서 `codex login`, `codex login status`로 로그인/상태 확인. 앱은 PATH 또는 `AUTOMONEY_CODEX_BIN`에서 실행 파일을 찾는다. 이는 현재 코드가 호출하는 명령 설명이며 설치 상태/구독 적합성은 이번에 실제 검증하지 않았다.
4. `/dashboard/content`에서 매거진/상품과 채널을 선택하여 생성 요청.
5. 앱이 `codex exec`를 실행하고 결과를 전송하면 라이브러리에 저장. CLI 미설치/미로그인/실행 오류/결과 파싱 실패 시 템플릿으로 대체될 수 있다.
6. `/dashboard/spaces`에서 SNS 계정을 연결하고 로그인 상태를 확인.
7. 승인된 콘텐츠의 ‘이 콘텐츠로 게시’ → `/dashboard/jobs`에서 스페이스·링크·미디어 확인 → 작업 등록 → 게시 승인.

직접 본문을 입력하거나 이미 공유된 콘텐츠를 게시하는 데는 GPT가 필수 조건이 아니다. 브라우저 게시 실행은 에이전트가 담당하고 Meta API 게시 실행은 Cloud가 담당한다. GPT/Codex는 초안 생성과 선택적 브라우저 복구에 사용된다. MCP/OAuth 연결은 automoney 도구에 접근하는 통로이며 Codex 설치·로그인을 대신하지 않는다.

위험 항목은 코드 경로상 발견이며 운영 공격/중복 게시를 재현했다는 의미가 아니다.

## 권장 구현 순서

1. 배포/데이터 위치 대조와 모바일 메뉴 복구.
2. 첫 시작 화면: 소재 준비 → PC 연결 → AI 로그인 → SNS 연결 → 첫 게시를 한 흐름으로 제공.
3. 콘텐츠 화면: 운영 제공/내 생성 구분, 빈 상태별 원인·다음 행동, 생성 작업 상태와 템플릿 대체 사유 표시.
4. 게시 화면: 채널·계정·본문·링크·미디어 검증을 통합하고 영상 없는 숏폼은 준비 필요로 표시.
5. KYC 소유권 결합, 승인 정책, 클릭 후 불명확 상태의 재게시 금지를 테스트로 보강.
6. 신규 USER 계정에서 모바일·데스크톱 각각 첫 게시 전 단계까지 E2E. 실제 SNS 게시 자체는 허용된 계정/콘텐츠로 별도 검증.

이번 작업은 분석과 보고서 작성이다. 애플리케이션 코드·운영 데이터·배포 설정은 변경하지 않았다.
