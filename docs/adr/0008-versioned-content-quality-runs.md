# ADR-0008 콘텐츠 품질은 버전 계약과 실행 스냅샷으로 보장

- 상태: 채택 (2026-09-22)
- 맥락: LLM은 같은 입력에도 문장을 다르게 만들 수 있다. 기존 구현은 상품과 채널만 잡에 전달하고 Codex를 한 번 호출했으며, 누락·실패 결과를 템플릿으로 보완해도 잡 전체를 성공으로 기록했다. 프롬프트·평가기·브랜드 기준·브리프가 저장되지 않아 결과의 차이를 설명하거나 같은 조건으로 재실행할 수 없었다.
- 결정: automoney가 보장하는 대상은 동일 문장이 아니라 **동일한 근거, 채널 규격, 브랜드 규칙, 품질 하한**이다. 모든 일괄 제작은 `contentRuns` 실행으로 기록하고, 시작 시 브리프·상품/이미지·`ContentProductionStandard`를 불변 스냅샷으로 저장한다. 잡과 콘텐츠는 `runId`, 실행 명세 해시, 실제 잡 입력 해시, 정규화 출력 해시, 워크플로·프롬프트·평가기 버전, 데스크톱 버전, provider와 생성 시도 번호를 보존한다.
- 결정: 기본 운영 기준은 서버가 소유한 `ATTRANGS_STANDARD_KO_V2`다. 클라이언트는 기준 ID·버전·이름·Codex 필수·최대 3회를 바꿀 수 없고 점수·이모지·금칙만 더 엄격하게 만들 수 있다. Codex 생성 필수, 최소 92점, 채널당 이모지 최대 2개, 카탈로그에 있는 상품명·가격만 사실로 사용한다. 최소 본문량, 상품·핵심 메시지 관련성, 근거 없는 주장, 가격 불일치, 필수 CTA·해시태그·숏폼 대본 길이/구조 누락은 점수로 상쇄할 수 없는 차단 조건이다. 광고 표기 누락은 서버가 `#광고`로 필수 보정하고 보정 결과를 다시 평가한다.
- 결정: 데스크톱은 첫 생성 후 실패 코드와 허용 근거만 넣어 실패 채널을 다시 생성한다. 3회 후에도 통과하지 못하거나 Codex를 사용할 수 없으면 템플릿은 검토 가능한 초안으로만 남긴다. 템플릿 결과를 Codex 결과로 표시하거나 자동 승인하지 않는다.
- 결정: V2 잡은 데스크톱 0.1.11 이상에서만 요청·claim할 수 있고 각 조각의 provider가 반드시 있어야 한다. 구버전 형태처럼 잡 전체 provider만 있고 조각별 provenance가 없으면 `PROVENANCE_MISSING` 초안으로 격리한다.
- 결정: 생성 잡의 `SUCCEEDED`는 실행이 끝났다는 뜻이고 품질 합격과 분리한다. 서버가 같은 버전 계약으로 다시 평가한다. 자동 게이트를 통과한 조각도 `DRAFT`로 저장하고 사람이 원본 상품·톤·이미지·링크를 대조해 승인해야 `APPROVED`가 된다. 수정하면 다시 초안이 되며 수퍼어드민도 실패 기준을 우회할 수 없다. 실행 완료 조건은 선택 상품 수 × 채널 수의 예상 산출물 전체가 만들어지고 모두 사람 승인까지 끝난 것이다.
- 결정: 브리프는 최소한 목적(`DISCOVERY|ENGAGEMENT|CONVERSION`), 말투, CTA, 대상 고객, 선택 핵심 메시지를 포함한다. 브라우저 로컬 상태가 아니라 서버 실행에 저장하므로 새로고침과 다른 PC에서도 같은 실행을 이어갈 수 있다.

## 결과

- 데스크톱 버전과 실제 잡 입력·출력 해시가 남아 어떤 조건으로 무엇을 생성·승인했는지 감사할 수 있다. 모델명은 실행기가 보고한 경우에만 기록한다.
- 가격과 규칙이 같은 스냅샷에서 동일하게 평가되므로 품질 하한을 회귀 테스트로 고정할 수 있다.
- 템플릿 폴백과 교정 실패가 성공처럼 숨겨지지 않고 검토 대상으로 드러난다.
- 계약을 바꿀 때는 버전을 올려야 한다. 진행 중인 과거 실행의 스냅샷은 새 기준으로 암묵적으로 바뀌지 않는다.
- 미디어 사용권의 구조화된 증빙과 모든 상품 속성의 필드별 근거 봉투는 후속 확장하되, 현재는 보수적 자동 차단과 필수 사람 승인을 함께 적용한다.

## 완료 정의

1. 실행마다 브리프·기준·상품/이미지 스냅샷·명세 해시와 정확한 잡 목록이 저장된다.
2. 요청 채널별 결과가 정확히 하나이며 provider·시도 번호·잡 입력 해시·출력 해시·데스크톱 버전을 알 수 있다.
3. 가격 불일치, 금칙 표현, 필수 필드 누락, Codex 필수 위반은 자동 승인 0건이다.
4. 실패 채널은 최대 3회까지만 교정하고 이후 `DRAFT/REVIEW_REQUIRED`로 남는다.
5. 같은 실행 화면은 새로고침 후에도 과거 실행 결과와 섞이지 않는다.
6. 계약·프롬프트·평가기·실제 잡 입력·출력 변경은 버전 또는 해시 변경으로 탐지된다.
7. 자동 게이트 통과 후 사람 승인 전에는 공유·예약·게시할 수 없다.
